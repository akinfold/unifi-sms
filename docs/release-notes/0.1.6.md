# UniFi SMS 0.1.6

Version 0.1.6 fixes security issues in authentication, credential storage, network operations, and image publication. Existing administrator accounts, device and forwarding settings, API keys, and SMS archives are preserved when you keep the same data volume.

## Security fixes

- Encrypt saved SMTP passwords at rest, including existing passwords during the automatic database migration. The persistent application secret remains in the data volume; protect the complete volume and its backups as secrets.
- Limit failed administrator logins and invalid integration-key attempts. New REST API and MCP keys use constant-time keyed verification; existing keys continue to work and migrate after successful authentication.
- Trust forwarded client addresses and HTTPS headers only from explicitly configured proxy addresses.
- Apply total deadlines to SSH commands and webhook requests, including stalled connections, DNS resolution, and slow responses.
- Reject malformed JSON, non-finite numbers, oversized integers, and invalid Unicode with bounded error responses.
- Pin the Python base image by digest and install runtime dependencies from a wheel hash lock.

REST API, MCP, email forwarding, and webhooks retain their existing configuration and remain optional.

## Checks before publication

Both native **Linux AMD64 and ARM64** jobs must pass before publication to GHCR or Docker Hub. They run security regressions, dependency and secret checks, and container tests for:

- Fresh installation and administrator creation.
- Upgrade preservation of the administrator account, settings, credentials, trusted device keys, sessions, and SMS.
- SMS import, database storage, device slot cleanup, and email delivery using simulated LTE Pro and SMTP servers.
- Email statuses, sending times, and hiding statuses when forwarding is disabled.
- REST API and MCP key authentication, rotation, revocation, and SMS CRUD.
- Webhook delivery, retries, secret headers, duplicate handling, and delivery statuses in Chromium.

The workflow publishes the images that passed these tests without rebuilding them, verifies their digests in both registries, and updates `latest` to the same release. Tests use disposable volumes and synthetic data.

## Upgrade from 0.1.5

Back up the **entire data volume** first. Keep the same Compose project and volume; do not run `docker compose down -v`.

For the [published-image Compose file](../../compose.ghcr.yaml), set `IMAGE_TAG=0.1.6` in the `.env` file beside `compose.yaml`, then run:

```sh
docker compose pull
docker compose up -d
```

If your Compose file uses a fixed image tag, change it to `ghcr.io/akinfold/unifi-sms:0.1.6` or `docker.io/akinfold/unifi-sms:0.1.6` before running those commands. Database migrations run automatically at startup. Existing API keys do not need to be regenerated.

**HTTPS reverse proxy users:** `TRUST_PROXY=1` now also requires `TRUSTED_PROXY_CIDRS` to list the immediate proxy addresses as seen by the container. Add this environment variable to older Compose files; the current release Compose file already passes it through. See [HTTPS configuration](../nas-maintenance.md#optional-https-access) before upgrading. Direct HTTP access does not need these settings.

Older backups may contain plaintext SMTP passwords. Encrypt and restrict access to them. See [backup and restore](../nas-maintenance.md#back-up-the-complete-data-volume).
