# UniFi SMS 0.1.5

Version 0.1.5 adds REST API, MCP, and webhook integrations. All three are disabled by default and can be configured in the web interface. Existing device connections, email forwarding, administrator accounts, and SMS archives continue to use the same data volume.

## New integrations

- **REST API:** list, search, read, create, update, and delete SMS archive records at `/api/v1/messages/`.
- **MCP:** connect a client that supports Streamable HTTP and a custom Bearer header at `/mcp/`. The tools are `list_sms`, `get_sms`, `create_sms`, `update_sms`, and `delete_sms`.
- **Access keys:** generate or enter separate keys for REST API and MCP in **Settings → API and MCP**. Only key hashes are stored. Rotate or revoke keys from the same page; the administrator's browser session does not authorize API requests.
- **Webhook forwarding:** send new, complete imported SMS as JSON POST requests. Configure the destination and an optional secret header in **Settings → Webhooks**. Secrets are encrypted at rest using the persistent application secret.
- **Delivery status:** show webhook pending, error, or sent status in the inbox and message reader, with sending times for successful deliveries. Disabling forwarding hides its statuses and pauses pending deliveries.

Creating an archive record through REST API or MCP does not send a cellular SMS or trigger forwarding. Each key grants read and write access to the entire archive. Webhooks retry failed deliveries using a stable event ID and `Idempotency-Key`; receivers should deduplicate events.

See the [integration guide](../integrations.md) for configuration, request examples, payloads, and retry behavior.

## Release checks

Before images can be published to either GHCR or Docker Hub, the release workflow must pass checks for:

- Fresh installation and administrator creation.
- Upgrade preservation of accounts, settings, encrypted credentials, trusted host keys, sessions, and SMS.
- The full SMS import, archive, device cleanup, and email delivery cycle using simulated servers.
- Email statuses, sending times, and hiding statuses when forwarding is disabled.
- REST API and MCP authentication, key rotation and revocation, and SMS CRUD, including an official MCP SDK client.
- Webhook delivery, retries, secret headers, duplicate handling, and browser display of delivery statuses and times.

These checks use disposable containers and synthetic data. They do not access a live LTE Pro or send email to real recipients.

## Upgrade from 0.1.4

Back up the **entire data volume** first. It contains the database, credentials, trusted host keys, and application secret. Keep the same Compose project and volume; do not run `docker compose down -v`.

For the [published-image Compose file](../../compose.ghcr.yaml), set `IMAGE_TAG=0.1.5` in the `.env` file beside `compose.yaml`, then run:

```sh
docker compose pull
docker compose up -d
```

If your Compose file uses a fixed image tag, change it to `ghcr.io/akinfold/unifi-sms:0.1.5` or `docker.io/akinfold/unifi-sms:0.1.5` before running those commands.

Database migrations run automatically at startup and add the integration settings and webhook delivery tables. The new integrations remain disabled until you enable them. No new environment variables are required.

See [backup and restore](../nas-maintenance.md#back-up-the-complete-data-volume) for backup instructions.
